CONDICIONALES: CUANDO TU PROGRAMA PIENSA

Los condicionales son estructuras que permiten que un programa tome decisiones.
Funcionan con una lógica simple:
evaluar una condición y, según si se cumple o no, ejecutar ciertas instrucciones.
En otras palabras, un condicional le dice a la computadora: "si pasa esto, haz esto; si no, haz otra cosa".

Ejemplo de la vida real:
Imagina esta situación:
Si tienes dinero, compras comida. Si no tienes dinero, no compras. Aquí hay una decisión basada en una condición, la idea es esta:

Si (condición) entonces
hacer algo
si no
hacer otra cosa

Ejemplo en programación (Java): 
int dinero = 10;

if (dinero > 5) {
    System.out.println("Puedes comprar comida");
 } else {
    System.out.println("No te alcanza");
}

int dinero = 10; Se crea una variable que guarda cuánto dinero tienes if (dinero > 5) Se evalúa la condición: ¿10 es mayor que 5?, Si!
→ Como la condición es verdadera, se ejecuta: "Puedes comprar comida".
else {} solo se ejecuta si la condición es falsa

Operadores importantes:
Operador Simbolo
Mayor que >
Menor que <
Mayor o igual >=
Menor o igual <=
Igual ==
Diferente de !=

Operadores Logicos:

(&&, ||, !) Estos operadores se usan dentro de los condicionales para combinar o modificar condiciones. Piensa que trabajas con respuestas de tipo verdadero o falso.

&&

verdadero && verdadero → verdadero
verdadero && falso → falso
falso && verdadero → falso
falso && falso → falso

||

verdadero || verdadero → verdadero
verdadero || falso → verdadero
falso || verdadero → verdadero
falso || falso → falso

! (Negacion)

Si era falso, se vuelve verdadero y viceversa.


else if (múltiples decisiones)

Se usa cuando tienes varias opciones posibles, pero solo una se ejecuta. 

int nota = 75;

if (nota >= 90) {
    System.out.println("Excelente");
} else if (nota >= 70) {
    System.out.println("Aprobado");
} else if (nota >= 50) {
    System.out.println("Regular");
} else {
    System.out.println("Reprobado");
}

Se evalúa de arriba hacia abajo
Cuando una condición es verdadera, se ejecuta y se detiene
Las demás ya no se revisan

if anidados (if dentro de otro if)

Se usan cuando necesitas validar algo dentro de otra condición. 

int edad = 20;
boolean pago = true;

if (edad >= 18) {
    if (pago == true) {
        System.out.println("Puede entrar");
    } else {
        System.out.println("Debe pagar");
    }
} else {
    System.out.println("Menor de edad");
}

Primero se evalúa una condición. Si es verdadera, entonces se evalúa otra dentro.

ESTRUCTURAS DE CONTROL: AUTOMATIZA PROCESOS

Las estructuras de control son fundamentales en la programación, ya que permiten controlar el flujo de ejecución de un programa.
Gracias a ellas, es posible repetir instrucciones, tomar decisiones y automatizar procesos.
En esta seccion aprenderás a utilizar los ciclos repetitivos más importantes: for, while y do while, además de comprender el uso de contadores y acumuladores, herramientas esenciales para resolver problemas de manera eficiente.

Ciclo FOR

El ciclo for se utiliza cuando sabemos cuántas veces queremos repetir una instrucción. 

for (inicialización; condición; incremento) {
   // instrucciones
}
Ejemplo Practico

Se desea contar del 1 al 10 usando un blucle for

public class Main {
    public static void main(String[] args) {
        for (int i = 1; i <= 10; i++) {
            System.out.println(i);
        }
    }
}
int i = 1 → inicia el contador.
i <= 10 → condición para seguir.
i++ → incrementa en 1.

CICLO WHILE

El ciclo while repite instrucciones mientras una condición sea verdadera. 

while (condición) {
   // instrucciones
}
Ejemplo Prectico

Se desea contar de 1 al 5 usando el bucle while

public class Main {
    public static void main(String[] args) {
        int i = 1;

        while (i <= 5) {
            System.out.println(i);
            i++;
        }
    } 
}

Explicacion del Ejemplo:

1. Se crea una variable llamada contador con valor 1.
2. El ciclo verifica si contador <= 5.
3. Si se cumple, imprime el número.
4. Luego aumenta el contador con contador++.
Cuando contador llega a 6, la condición ya no se cumple y el ciclo termina.

El programa seguirá ejecutándose mientras i sea menor o igual a 5.

Se usa cuando no sabemos exactamente cuántas veces se repetirá una acción, ya que depende de que una condición se cumpla.
Idea clave: Primero evalúa la condición y, si es verdadera, ejecuta el bloque de instrucciones.
NO OLVIDES ESTO!

Es un error muy comun en los Principiantes "Olvidar actualizar la variable."

Esto esta incorrecto:

int i = 1;

while (i <= 5) {
   System.out.println(i);
}

Esto genera un bucle infinito porque i nunca cambia, lo q podria petar tu pc 😂.

lo correcto es usar la variable i++;

Programacion Orientada a Objetos (POO)
ENTENDIENDO LAS BASES

La Programación Orientada a Objetos (POO) es un paradigma de programación que organiza el software en objetos, los cuales representan entidades del mundo real mediante atributos y comportamientos. Cada objeto posee características propias, conocidas como atributos, y puede realizar acciones específicas, llamadas métodos o comportamientos. Este enfoque permite modelar problemas de una forma más cercana a la realidad, facilitando el diseño, desarrollo y mantenimiento de las aplicaciones. Además, la POO promueve principios como la encapsulación, la herencia, el polimorfismo y la abstracción, lo que favorece la reutilización del código, mejora su organización hace que los programas sean más escalables y fáciles de comprender.

Que es un Objeto?

Un objeto es una instancia de una clase.

Por ejemplo:
Un carro tiene atributos: color, marca, velocidad.
Un carro tiene comportamientos: acelerar, frenar, encender.
En Programacion: 
Carro miCarro = new Carro();

Carro: Clase
miCarro: Objeto

Que es una Clase

Una clase es un molde o plantilla que define las características y comportamientos de un tipo de objeto.
Es como un plano que describe cómo se ve y qué puede hacer un objeto, pero no es el objeto en sí.

Ejemplo:
La clase "Perro" podría tener atributos como "raza", "edad" y "color", y métodos como "ladrar()" o "comer()".
Cuando creas un objeto a partir de esta clase, como "miPerro", ese objeto tendrá sus propios valores para esos atributos y podrá usar los métodos definidos en la clase.
Ejemplo en Java: 
// 1. Definimos la clase "Perro" (El molde)
class Perro {
    // Atributos (Características)
    String raza;
    int edad;
    String color;

    // Métodos (Acciones)
    void ladrar() {
        System.out.println("¡Guau! ¡Guau!");
    }

    void comer() {
        System.out.println("El perro está comiendo sus croquetas.");
    }
}

// 2. Clase principal para ejecutar el programa y crear el objeto
public class Main {
    public static void main(String[] args) {
        
        // Creamos el objeto "miPerro" a partir de la clase "Perro"
        Perro miPerro = new Perro();

        // Le asignamos valores propios a sus atributos
        miPerro.raza = "Labrador";
        miPerro.edad = 3;
        miPerro.color = "Dorado";

        // Mostramos las características del objeto en la consola
        System.out.println("Mi perro es un " + miPerro.raza + " de color " + miPerro.color + " y tiene " + miPerro.edad + " años.");

        // Ponemos al objeto a usar sus métodos
        miPerro.ladrar();
        miPerro.comer();
    }
}

PILARES FUNDAMENTALES

La Programación Orientada a Objetos (POO) se basa en cuatro pilares que permite desarrollar programas más organizados, reutilizables, seguros y fáciles de mantener, facilitando la creación de aplicaciones de mayor complejidad
Estos pilares son:

ENCAPSULAMIENTO:
El encapsulamiento consiste en proteger los datos internos de un objeto, restringiendo el acceso directo y controlándolo mediante métodos.
Se logra usando:

- private
- public
- getters
- setters

Ejemplo en Java: 

public class Cuenta {
    private double saldo;

    public void setSaldo(double saldo) {
        this.saldo = saldo;
    }

    public double getSaldo() {
        return saldo;
    }
}

1. La variable saldo es privada, lo que significa que no puede ser accedida directamente desde fuera de la clase.
2. Se proporcionan métodos públicos (setSaldo y getSaldo) para permitir el acceso controlado al saldo.
3. Esto protege la integridad de los datos y permite validar o controlar cómo se accede y modifica el saldo, evitando cambios no deseados o inconsistentes.

Videos recomendados:

ABSTRACCION:

La abstracción es un principio de la programación orientada a objetos que permite simplificar la complejidad de un sistema al enfocarse en los aspectos esenciales y relevantes de un objeto, ignorando los detalles innecesarios.
Se logra mediante el uso de clases abstractas e interfaces, permitiendo definir comportamientos y características comunes sin necesidad de implementar todos los detalles, lo que facilita la reutilización del código y mejora la organización del software.
ventajas:
- Facilita la comprensión del sistema al centrarse en lo esencial.
- Permite la creación de jerarquías de clases y relaciones entre objetos.
- Fomenta la reutilización del código al definir comportamientos comunes en clases abstractas e interfaces.

Video recomendado:

Ejemplo Real:

Un automóvil es un buen ejemplo de abstracción.
Cuando conduces, utilizas elementos como:
- Acelerar
- Frenar
- Girar
- Encender

Pero no necesitas saber exactamente cómo funciona el motor, cómo se inyecta el combustible o cómo funciona el sistema de frenos. Solo utilizas las funciones que necesitas y el automóvil se encarga de los procesos internos.

Ejemplo en Java: 

abstract class Automovil {
// Métodos abstractos
public abstract void acelerar();
public abstract void frenar();
public abstract void girar();
public abstract void encender();
}

class carro extends Automovil {

    @Override
    public void acelerar() {
        System.out.println("El carro está acelerando.");
    }
    public void frenar() {
        System.out.println("El carro está frenando.");
    }
    public void girar() {
        System.out.println("El carro está girando.");
    }
    public void encender() {
        System.out.println("El carro está encendido.");
    }
}

HERENCIA:

La herencia es un principio de la programación orientada a objetos que permite crear nuevas clases basadas en clases existentes, heredando sus atributos y métodos.
Esto facilita la reutilización del código, ya que las clases derivadas pueden aprovechar la funcionalidad de las clases base y agregar o modificar comportamientos según sea necesario.
La herencia promueve la organización jerárquica de las clases y fomenta la creación de relaciones entre objetos, lo que mejora la estructura y mantenibilidad del software.

Ventajas de la herencia:
- Reutilización de código: Las clases derivadas pueden aprovechar la funcionalidad de las clases base, evitando la duplicación de código.
- Organización jerárquica: Permite estructurar las clases en una jerarquía, facilitando la comprensión y el mantenimiento del software.
- Extensibilidad: Las clases derivadas pueden agregar o modificar comportamientos según sea necesario, adaptándose a nuevas necesidades sin afectar la clase base.

Ejemplo en Java: 
class Animal {
    void comer() {
        System.out.println("El animal está comiendo.");
    }
}

En este ejemplo, la clase Animal tiene un método comer() que imprime un mensaje indicando que el animal está comiendo. 

class Perro extends Animal {
    void ladrar() {
        System.out.println("El perro está ladrando.");
    }
}

En este ejemplo, la clase Perro hereda de la clase Animal y agrega un método ladrar() que imprime un mensaje indicando que el perro está ladrando.

Videos Recomendados:

Es una buena práctica usar la herencia para modelar relaciones "es un" entre clases. Por ejemplo, un Perro "es un" Animal, por lo que tiene sentido que la clase Perro herede de la clase Animal.
Es muy importante tener en cuenta que la herencia debe usarse con cuidado, ya que un uso excesivo o inapropiado puede llevar a una jerarquía de clases complicada y difícil de mantener.
Es una de las características más poderosas de la programación orientada a objetos, pero también requiere un buen diseño y comprensión de las relaciones entre clases.


POLIMORFISMO:

El polimorfismo es un principio de la programación orientada a objetos que permite que un objeto pueda tomar diferentes formas o comportamientos según el contexto en el que se utilice.
Esto significa que una misma interfaz o método puede ser implementado de distintas maneras por diferentes clases, lo que permite tratar a los objetos de manera uniforme y flexible.
El polimorfismo facilita la reutilización del código, mejora la extensibilidad del software y permite crear sistemas más dinámicos y adaptables a cambios futuros.

Ejemplo en Java: 
class Animal {
    void hacerSonido() {
        System.out.println("El animal hace un sonido.");
    }
}
class Perro extends Animal {
    @Override
    void hacerSonido() {
        System.out.println("El perro ladra: ¡Guau! ¡Guau!");
    }
}
class Gato extends Animal {
    @Override
    void hacerSonido() {
        System.out.println("El gato maúlla: ¡Miau! ¡Miau!");
    } 
}

GLOSARIO COMPLETO

Programación Orientada a Objetos (POO): Es un paradigma de programación que organiza el código alrededor de objetos. Los objetos representan entidades que tienen datos y comportamientos. La POO permite crear programas más organizados, reutilizables, fáciles de mantener y ampliar.
Paradigma de programación: Es una forma o estilo de organizar y desarrollar programas. La Programación Orientada a Objetos es uno de los paradigmas más utilizados.
Clase: Es una plantilla o molde que define cómo serán los objetos. Una clase puede contener atributos, métodos y constructores. Por ejemplo, una clase Persona puede definir que todas las personas tendrán un nombre y una edad.
Objeto: Es una instancia concreta de una clase. Si Persona es el molde, un objeto puede ser una persona específica llamada "Carlos" con 20 años. Cada objeto puede tener sus propios valores.
Instancia: Es un objeto creado a partir de una clase. Cuando usamos new en Java normalmente estamos creando una nueva instancia de una clase.
Estado: Es la información que tiene un objeto en un momento determinado. Está representado principalmente por sus atributos. Por ejemplo, una persona puede tener el estado: nombre = "Carlos", edad = 20.
Comportamiento: Son las acciones que un objeto puede realizar. En Java, estas acciones normalmente se representan mediante métodos.
Identidad: Es lo que permite distinguir un objeto de otro. Dos objetos pueden tener los mismos datos, pero seguir siendo objetos diferentes.
Atributo: Es una variable declarada dentro de una clase que representa una característica o dato de los objetos. Por ejemplo, nombre, edad y precio pueden ser atributos.
Variable de instancia: Es un atributo que pertenece a cada objeto individualmente. Cada objeto puede tener un valor diferente para esa variable.
Variable de clase: Es una variable declarada con static. Pertenece a la clase y es compartida por las instancias de esa clase.
Método: Es un bloque de código que representa una acción o comportamiento de un objeto o de una clase. Puede recibir datos mediante parámetros y puede devolver un resultado.
Parámetro: Es una variable que aparece en la declaración de un método y recibe un valor cuando el método es llamado.
Argumento: Es el valor que realmente enviamos a un método cuando lo llamamos.
Valor de retorno: Es el resultado que un método devuelve mediante la palabra return.
void: Indica que un método no devuelve ningún valor.
Firma de un método: Está relacionada con el nombre del método y sus parámetros. En Java permite distinguir métodos sobrecargados.
Constructor: Es un método especial utilizado para inicializar objetos. Tiene el mismo nombre de la clase y no tiene tipo de retorno. Se ejecuta cuando se utiliza new.
Constructor por defecto: Es el constructor sin parámetros que el compilador puede proporcionar automáticamente cuando la clase no declara ningún constructor.
Constructor personalizado: Es un constructor creado por el programador para inicializar el objeto con los datos que necesite.
this: Es una referencia al objeto actual. Se utiliza, entre otras cosas, para diferenciar atributos de parámetros cuando tienen el mismo nombre.
new: Es una palabra clave utilizada para crear objetos o instancias de clases.
Referencia: Es una variable que permite acceder a un objeto almacenado en memoria. La variable no contiene directamente todo el objeto, sino una referencia al mismo.
null: Representa la ausencia de una referencia a un objeto. Una variable de tipo objeto puede tener el valor null.
Memoria: Es el espacio donde el programa almacena temporalmente datos y objetos mientras se está ejecutando.
Heap: Es una zona de memoria donde Java almacena principalmente los objetos creados dinámicamente.
Stack: Es una zona de memoria utilizada para almacenar información relacionada con las llamadas a métodos, como variables locales y referencias.
Garbage Collector: Es el mecanismo automático de Java encargado de identificar y liberar memoria ocupada por objetos que ya no pueden ser utilizados por el programa.
Encapsulamiento: Es el principio que protege los datos internos de un objeto, evitando que sean modificados directamente sin control. Normalmente se logra utilizando atributos privados y métodos públicos para acceder a ellos.
Abstracción: Permite representar solamente las características importantes de un objeto y ocultar detalles internos que no son necesarios para utilizarlo.
Herencia: Permite crear una clase nueva a partir de otra clase existente. La nueva clase puede reutilizar atributos y métodos de la clase padre.
Polimorfismo: Permite que una misma referencia pueda utilizar objetos de diferentes clases y que el comportamiento ejecutado dependa del objeto real.
Clase padre: Es la clase de la que otra clase hereda características y comportamientos. También puede llamarse superclase.
Clase hija: Es una clase que hereda de otra clase. También se conoce como subclase.
Superclase: Es otra forma de llamar a la clase padre dentro de una relación de herencia.
Subclase: Es otra forma de llamar a la clase hija dentro de una relación de herencia.
super: Es una palabra clave utilizada para acceder a elementos de la clase padre, como constructores o métodos.
extends: Es la palabra clave utilizada en Java para indicar que una clase hereda de otra clase.
implements: Es la palabra clave utilizada cuando una clase implementa una o más interfaces.
Interface: Es una estructura que define un contrato que las clases pueden implementar. Permite establecer comportamientos que una clase debe proporcionar.
Contrato: Es el conjunto de reglas que una clase debe cumplir cuando implementa una interfaz.
Clase abstracta: Es una clase que sirve como base para otras clases y que no puede ser instanciada directamente. Puede contener métodos normales y métodos abstractos.
Método abstracto: Es un método declarado sin implementación dentro de una clase abstracta. Las clases hijas deben proporcionar su implementación cuando corresponda.
abstract: Es una palabra clave utilizada para declarar clases y métodos abstractos.
public: Es un modificador de acceso que permite que un elemento sea accesible desde cualquier clase que tenga acceso a él.
private: Es un modificador de acceso que limita el acceso directo al elemento únicamente a la clase donde fue declarado. Es muy utilizado para aplicar encapsulamiento.
protected: Permite acceder a un elemento desde la misma clase, clases del mismo paquete y clases hijas según las reglas de acceso de Java.
default: Cuando no se escribe un modificador de acceso, el elemento tiene acceso de paquete. Puede utilizarse desde clases que pertenecen al mismo paquete.
Modificador de acceso: Determina desde dónde puede utilizarse una clase, atributo, método o constructor. Los principales son public, private y protected, además del acceso de paquete.
static: Indica que un atributo o método pertenece a la clase y no a una instancia específica. Puede utilizarse sin crear un objeto.
Método estático: Es un método declarado con static. Se puede llamar utilizando el nombre de la clase.
Atributo estático: Es un atributo compartido por todas las instancias de una clase.
final: Indica que algo no puede modificarse de la misma manera que un elemento normal. Una variable final no puede recibir otro valor después de ser inicializada, un método final no puede sobrescribirse y una clase final no puede heredarse.
Constante: Es un valor que no debe cambiar durante la ejecución del programa. En Java normalmente se representa utilizando static final.
this(): Permite llamar a otro constructor de la misma clase. Debe utilizarse como primera instrucción del constructor.
super(): Permite llamar al constructor de la clase padre. Debe utilizarse como primera instrucción del constructor cuando se utiliza explícitamente.
Sobrecarga de métodos (Overloading): Ocurre cuando una misma clase tiene varios métodos con el mismo nombre pero diferentes parámetros. Permite realizar operaciones similares con diferentes tipos o cantidades de datos.
Sobrescritura de métodos (Overriding): Ocurre cuando una clase hija proporciona su propia implementación de un método heredado de la clase padre.
@Override: Es una anotación que indica que un método está sobrescribiendo un método heredado. Ayuda a detectar errores en el código.
@Overload: No es una anotación estándar necesaria en Java para sobrecarga. La sobrecarga se identifica automáticamente mediante diferentes listas de parámetros.
Binding: Es el proceso mediante el cual Java determina qué implementación de un método debe utilizar. Puede ocurrir en diferentes momentos dependiendo del tipo de llamada.
Enlace estático: También llamado early binding. Se determina durante la compilación en situaciones como la sobrecarga de métodos.
Enlace dinámico: También llamado late binding. En métodos sobrescritos, Java determina durante la ejecución qué implementación debe utilizar según el objeto real.
Polimorfismo de compilación: Se relaciona principalmente con la sobrecarga de métodos, donde el compilador determina qué método utilizar según los parámetros.
Polimorfismo de ejecución: Se produce principalmente mediante herencia e interfaces y permite que una referencia de un tipo general ejecute el comportamiento específico del objeto real.
Upcasting: Es convertir o tratar un objeto de una clase hija como si fuera una referencia de su clase padre. Generalmente es seguro y puede realizarse automáticamente.
Downcasting: Es convertir una referencia de una clase padre hacia una clase hija. Debe hacerse con cuidado porque el objeto realmente debe ser una instancia de la clase hija.
instanceof: Es un operador que permite comprobar si un objeto pertenece a una determinada clase o implementa una determinada interfaz.
Clase Object: Es la clase raíz de la jerarquía de clases de Java. Todas las clases heredan directa o indirectamente de Object.
toString(): Es un método heredado de Object que permite obtener una representación textual de un objeto. Puede sobrescribirse para mostrar información útil.
equals(): Es un método utilizado para comparar objetos según una definición de igualdad. Puede sobrescribirse para establecer qué significa que dos objetos sean iguales.
==: Cuando se utiliza con referencias de objetos, normalmente compara si ambas referencias apuntan al mismo objeto. No debe confundirse con equals().
hashCode(): Devuelve un valor entero asociado al objeto. Es especialmente importante cuando los objetos se utilizan en estructuras como HashMap y HashSet.
Contrato equals-hashCode: Si dos objetos son considerados iguales mediante equals(), deben devolver el mismo valor mediante hashCode().
Composición: Es una relación fuerte entre objetos donde un objeto contiene o está formado por otros objetos. Cuando el objeto principal desaparece, los objetos que forman parte de él normalmente dejan de tener sentido dentro de esa relación.
Agregación: Es una relación entre objetos en la que un objeto contiene otros objetos, pero estos pueden existir independientemente del objeto que los agrupa.
Asociación: Representa una relación general entre dos clases. Por ejemplo, un profesor puede estar relacionado con varios estudiantes.
Dependencia: Ocurre cuando una clase utiliza temporalmente otra clase para realizar una tarea.
Relación "es un": Representa normalmente una relación de herencia. Por ejemplo, un perro "es un" animal.
Relación "tiene un": Representa normalmente composición o agregación. Por ejemplo, un automóvil "tiene un" motor.
Acoplamiento: Representa el nivel de dependencia entre diferentes clases o componentes. Un bajo acoplamiento facilita modificar una parte del sistema sin afectar demasiado a las demás.
Cohesión: Indica qué tan relacionadas están las responsabilidades de una clase. Una clase con alta cohesión normalmente tiene responsabilidades relacionadas y bien definidas.
Responsabilidad: Es aquello que una clase debe conocer o hacer dentro de un sistema. Una buena POO busca asignar responsabilidades de manera clara.
Inmutabilidad: Significa que el estado de un objeto no puede cambiar después de haber sido creado. Las clases inmutables suelen utilizar atributos privados y finales y no proporcionan métodos que permitan modificar su estado.
Mutabilidad: Significa que el estado interno de un objeto puede cambiar después de haber sido creado.
Clase inmutable: Es una clase cuyos objetos no pueden cambiar su estado después de ser creados.
Getter: Es un método utilizado para obtener el valor de un atributo privado. Normalmente comienza con get.
Setter: Es un método utilizado para modificar el valor de un atributo privado. Normalmente comienza con set.
Encapsulamiento mediante getters y setters: Permite controlar cómo se consultan y modifican los atributos de una clase en lugar de permitir acceso directo a ellos.
Validación: Es el proceso de comprobar que los datos recibidos cumplen determinadas reglas antes de almacenarlos o utilizarlos.
Inyección de dependencias: Es una técnica en la que una clase recibe desde fuera los objetos que necesita en lugar de crearlos directamente. Esto ayuda a reducir el acoplamiento y facilita las pruebas.
Clase interna: Es una clase declarada dentro de otra clase. Puede utilizarse cuando una clase auxiliar solo tiene sentido dentro de la clase que la contiene.
Clase anidada estática: Es una clase declarada dentro de otra clase utilizando static. No necesita una instancia de la clase externa para ser utilizada.
Clase interna no estática: Es una clase declarada dentro de otra clase que está asociada a una instancia de la clase externa.
Clase local: Es una clase declarada dentro de un método o bloque de código.
Clase anónima: Es una clase sin nombre que se crea y utiliza normalmente en el mismo lugar donde se necesita. Fue muy utilizada antes de la popularización de las expresiones lambda.
Enum: Es un tipo especial utilizado para representar un conjunto fijo de constantes. Por ejemplo, los días de la semana o estados de un pedido.
enumeración: Es el concepto que representa un conjunto limitado y conocido de valores posibles. En Java se implementa mediante enum.
Record: Es una característica de Java diseñada para representar principalmente datos inmutables de forma compacta. El compilador genera automáticamente elementos como constructor, accesores, equals(), hashCode() y toString().
Sealed class: Es una clase que permite controlar qué clases pueden heredarse de ella. Se utiliza para limitar una jerarquía de herencia.
Permits: Se utiliza junto con clases selladas para indicar qué clases tienen permitido extender o implementar una determinada clase o interfaz.
Modularidad: Consiste en dividir un sistema grande en partes más pequeñas y organizadas que pueden desarrollarse y mantenerse de forma independiente.
Paquete (Package): Es una forma de organizar clases e interfaces relacionadas. También ayuda a controlar el acceso y evitar conflictos entre nombres.
import: Permite utilizar clases de otros paquetes sin tener que escribir su nombre completamente calificado.
package: Indica a qué paquete pertenece una clase. Normalmente aparece al inicio del archivo Java.
Nombre completamente calificado: Es el nombre completo de una clase incluyendo su paquete. Por ejemplo, java.util.ArrayList.
Interfaz funcional: Es una interfaz que contiene exactamente un método abstracto. Puede utilizarse con expresiones lambda.
@FunctionalInterface: Es una anotación que indica que una interfaz está diseñada para tener un único método abstracto.
Expresión lambda: Es una forma compacta de representar una función o comportamiento que puede utilizarse especialmente con interfaces funcionales.
Referencia a método: Permite utilizar un método existente como una implementación de una interfaz funcional mediante una sintaxis más corta.
Método default: Es un método dentro de una interfaz que puede tener una implementación. Permite agregar comportamiento a interfaces sin obligar inmediatamente a todas las clases implementadoras a definirlo.
Método static en una interfaz: Es un método que pertenece a la interfaz y puede ser llamado mediante el nombre de la interfaz.
Herencia múltiple: Es la posibilidad de heredar directamente de varias clases. Java no permite que una clase extienda múltiples clases, pero sí permite implementar múltiples interfaces.
Implementación múltiple: Una clase puede implementar varias interfaces, obteniendo diferentes contratos de comportamiento.
Interfaz vs clase abstracta: Una interfaz representa principalmente un contrato de comportamiento, mientras que una clase abstracta puede proporcionar una base común con estado y comportamiento compartido.
Principio de responsabilidad única: Indica que una clase debería tener una responsabilidad principal bien definida y una razón clara para cambiar.
Principio abierto/cerrado: Indica que el software debería estar abierto para extensión pero cerrado para modificaciones innecesarias.
Principio de sustitución de Liskov: Indica que los objetos de una clase hija deberían poder utilizarse donde se espera un objeto de la clase padre sin romper el comportamiento esperado del programa.
Principio de segregación de interfaces: Indica que es preferible utilizar interfaces pequeñas y específicas en lugar de obligar a las clases a implementar métodos que no necesitan.
Principio de inversión de dependencias: Indica que las partes importantes de un sistema deberían depender de abstracciones y no directamente de implementaciones concretas.
SOLID: Es un conjunto de cinco principios de diseño orientado a objetos: responsabilidad única, abierto/cerrado, sustitución de Liskov, segregación de interfaces e inversión de dependencias.
DRY (Don't Repeat Yourself): Principio que busca evitar repetir la misma lógica innecesariamente. La reutilización mediante métodos, clases y otras estructuras ayuda a mantener el código.
KISS (Keep It Simple): Principio que recomienda mantener las soluciones lo más simples y claras posible, evitando complejidad innecesaria.
YAGNI (You Aren't Gonna Need It): Principio que recomienda no desarrollar funcionalidades que actualmente no son necesarias.
Reutilización de código: Consiste en utilizar código existente nuevamente en diferentes partes del programa en lugar de escribir la misma solución desde cero. La POO facilita esto mediante clases, métodos, herencia y composición.
Modularización: Consiste en dividir un programa en componentes más pequeños y organizados para facilitar su comprensión y mantenimiento.
Acoplamiento bajo: Significa que las clases dependen poco unas de otras. Esto facilita los cambios y el mantenimiento.
Cohesión alta: Significa que los elementos de una clase están muy relacionados con una responsabilidad común.
Delegación: Consiste en hacer que un objeto encargue una tarea a otro objeto especializado en realizarla.
Composición sobre herencia: Es una recomendación de diseño que propone utilizar relaciones de composición cuando sea más adecuado, en lugar de crear jerarquías de herencia innecesariamente profundas.
Diseño orientado a objetos: Es el proceso de identificar objetos, responsabilidades y relaciones para construir un sistema utilizando principios de POO.
Modelo: Es una representación de una parte del sistema que contiene los datos y reglas necesarias para representar un concepto.
Entidad: Es un objeto que representa algo importante dentro del dominio de una aplicación, normalmente con identidad propia.
Objeto de valor: Es un objeto cuyo significado depende principalmente de sus valores y no de una identidad individual.
DTO (Data Transfer Object): Es un objeto utilizado principalmente para transportar datos entre diferentes partes de una aplicación.
POJO: Significa Plain Old Java Object. Es un objeto Java sencillo que no necesita heredar de una clase especial ni seguir un framework específico para representar sus datos y comportamiento.
Bean: Es un término utilizado para objetos Java que siguen determinadas convenciones, como tener constructor sin argumentos y métodos de acceso. El significado exacto depende del contexto.
JavaBean: Es una clase Java que tradicionalmente sigue convenciones como tener un constructor público sin argumentos, atributos privados y métodos getters/setters apropiados.
Objeto anémico: Es un objeto que contiene principalmente datos y muy poco comportamiento. Puede ser apropiado en algunos casos, pero puede ser problemático si las reglas del dominio quedan completamente fuera del objeto.
Clase utilitaria: Es una clase utilizada para agrupar métodos relacionados, normalmente estáticos, que realizan operaciones auxiliares.
Clase singleton: Es un patrón de diseño que busca garantizar que exista una única instancia de una clase y proporcionar un punto de acceso a ella. Debe utilizarse con cuidado porque puede introducir acoplamiento global.
Patrón de diseño: Es una solución general y reutilizable para problemas frecuentes de diseño de software. No es código que se copia literalmente, sino una idea de organización.
Singleton: Es un patrón creacional que restringe una clase a una única instancia en un determinado contexto.
Factory: Es un patrón utilizado para centralizar o encapsular la creación de objetos.
Factory Method: Es un patrón que permite delegar la creación de objetos a métodos especializados o a subclases.
Abstract Factory: Es un patrón que permite crear familias de objetos relacionados sin especificar directamente sus clases concretas.
Builder: Es un patrón utilizado para construir objetos complejos paso a paso, especialmente cuando tienen muchos parámetros opcionales.
Prototype: Es un patrón que crea nuevos objetos a partir de otros objetos existentes, normalmente mediante clonación o copia controlada.
Adapter: Es un patrón estructural que permite que dos componentes con interfaces incompatibles puedan trabajar juntos.
Decorator: Es un patrón que permite agregar responsabilidades o comportamientos a un objeto sin modificar directamente su clase.
Facade: Es un patrón que proporciona una interfaz sencilla para utilizar un sistema o conjunto de clases más complejo.
Proxy: Es un objeto que actúa como intermediario para controlar o gestionar el acceso a otro objeto.
Composite: Es un patrón que permite tratar objetos individuales y grupos de objetos de una manera uniforme.
Observer: Es un patrón que permite que varios objetos sean notificados cuando cambia el estado de otro objeto.
Strategy: Es un patrón que permite definir diferentes algoritmos o comportamientos y elegir cuál utilizar durante la ejecución.
State: Es un patrón que permite que el comportamiento de un objeto cambie dependiendo de su estado interno.
Command: Es un patrón que convierte una acción o solicitud en un objeto, permitiendo almacenarla, ejecutarla o deshacerla.
Template Method: Es un patrón que define la estructura general de un algoritmo y permite que las subclases personalicen determinados pasos.
MVC: Es un patrón arquitectónico que separa una aplicación en Modelo, Vista y Controlador. El modelo gestiona los datos y lógica, la vista presenta información y el controlador coordina las acciones.
Excepción: Es un evento que ocurre durante la ejecución y que puede interrumpir el flujo normal del programa. Java permite manejar excepciones mediante estructuras como try, catch y finally.
Exception: Es una clase de Java utilizada como base para muchas excepciones que pueden manejarse durante la ejecución de un programa.
RuntimeException: Es una categoría de excepciones que ocurren durante la ejecución y que no requieren obligatoriamente ser declaradas o capturadas por el compilador.
Checked Exception: Es una excepción que el compilador obliga a manejar o declarar en determinados casos.
Unchecked Exception: Es una excepción que no necesita ser obligatoriamente capturada o declarada. Generalmente pertenece a RuntimeException.
try: Define un bloque de código donde puede ocurrir una excepción.
catch: Permite capturar y manejar una excepción producida dentro de un bloque try.
finally: Es un bloque que normalmente se ejecuta después del procesamiento de try y catch, independientemente de si ocurrió una excepción, con algunas excepciones relacionadas con la terminación de la JVM.
throw: Permite lanzar manualmente una excepción desde el programa.
throws: Se utiliza en la declaración de un método para indicar que este puede lanzar determinadas excepciones.
Excepción personalizada: Es una clase de excepción creada por el programador para representar errores específicos de una aplicación o dominio.
Encadenamiento de excepciones: Consiste en conservar la causa original de una excepción cuando se lanza otra excepción, ayudando a conocer el origen del problema.
Genéricos: Permiten crear clases, interfaces y métodos que trabajan con diferentes tipos de datos manteniendo seguridad de tipos.
Tipo genérico: Es un tipo parametrizado que permite especificar qué tipo de dato manejará una estructura. Por ejemplo, ArrayList<String>.
Clase genérica: Es una clase que recibe uno o más tipos como parámetros.
Método genérico: Es un método que define sus propios parámetros de tipo y puede trabajar con diferentes tipos de datos.
List: Es una colección ordenada que permite almacenar elementos y puede contener elementos repetidos.
ArrayList: Es una implementación de List basada en un arreglo dinámico. Permite almacenar y acceder fácilmente a elementos mediante posiciones.
Set: Es una colección que normalmente no permite elementos duplicados según las reglas de igualdad de los objetos.
HashSet: Es una implementación de Set que utiliza una estructura basada en hashing para almacenar elementos.
Map: Es una estructura que almacena asociaciones entre claves y valores. Cada clave se utiliza para localizar un valor.
HashMap: Es una implementación de Map que almacena pares clave-valor utilizando hashing.
Collection: Es una interfaz de Java que representa una agrupación de objetos y sirve como base para varias estructuras de colecciones.
Iterable: Es una interfaz que permite recorrer objetos mediante mecanismos como el ciclo for-each.
Iterator: Es un objeto utilizado para recorrer elementos de una colección de manera controlada.
Comparable: Es una interfaz que permite definir un orden natural para objetos de una clase mediante el método compareTo().
Comparator: Es una interfaz que permite definir diferentes formas de comparar y ordenar objetos sin modificar necesariamente la clase de los objetos.
compareTo(): Es el método utilizado por Comparable para comparar un objeto con otro.
Orden natural: Es la forma predeterminada en que una clase define cómo deben ordenarse sus objetos.
Encapsulación de colecciones: Consiste en controlar el acceso a las colecciones internas de una clase para evitar modificaciones no deseadas desde fuera.
Inyección de dependencias: Es una técnica en la que los objetos necesarios para una clase se proporcionan desde el exterior, reduciendo la responsabilidad de crear directamente esas dependencias.
Acoplamiento: Es el grado de dependencia entre componentes. Un diseño con menor acoplamiento suele ser más flexible y fácil de mantener.
Cohesión: Es el grado en que los elementos de una clase trabajan juntos para cumplir una responsabilidad relacionada.
API: Es un conjunto de clases, métodos, interfaces y reglas que permite que diferentes partes de un software interactúen entre sí.
JDK: Es el Java Development Kit. Contiene herramientas necesarias para desarrollar aplicaciones Java, incluyendo el compilador.
JRE: Es el entorno necesario para ejecutar aplicaciones Java. En versiones modernas de Java, el concepto está integrado de forma diferente dentro de la distribución del JDK.
JVM: Es la Java Virtual Machine, encargada de ejecutar el bytecode de Java. Permite que los programas Java puedan ejecutarse sobre diferentes sistemas operativos que tengan una JVM compatible.
Bytecode: Es el código intermedio generado por el compilador de Java a partir del código fuente. La JVM interpreta o compila este código para ejecutarlo.
Compilador: Es el programa que transforma el código fuente Java en bytecode. El compilador principal de Java es javac.
Código fuente: Es el código escrito por el programador en un lenguaje como Java antes de ser compilado.
Archivo .java: Es un archivo que contiene código fuente Java.
Archivo .class: Es un archivo que contiene bytecode Java generado después de la compilación.
Main: Es el método que tradicionalmente sirve como punto de entrada para ejecutar una aplicación Java independiente.
public static void main: Es la declaración tradicional del método principal que permite iniciar la ejecución de muchas aplicaciones Java.
Tipo de dato: Indica qué clase de información puede almacenar una variable. Puede ser primitivo o de referencia.
Tipo primitivo: Es uno de los tipos básicos de Java que no son objetos, como int, double, char y boolean.
Tipo de referencia: Es un tipo que permite almacenar una referencia a un objeto. Las clases, interfaces, arreglos y enums se manejan como tipos de referencia.
Wrapper: Es una clase que representa un tipo primitivo como objeto. Por ejemplo, Integer representa int.
Autoboxing: Es la conversión automática de un tipo primitivo a su clase wrapper correspondiente.
Unboxing: Es la conversión automática de un objeto wrapper a su tipo primitivo correspondiente.
String: Es una clase de Java utilizada para representar cadenas de texto. Los objetos String son inmutables.
Inmutabilidad de String: Significa que una vez creado un objeto String, su contenido no puede cambiar. Las operaciones que parecen modificarlo realmente producen nuevos objetos.
StringBuilder: Es una clase utilizada para construir y modificar cadenas de texto de manera eficiente cuando se realizan muchas modificaciones.
Clase utilitaria Arrays: Proporciona métodos para trabajar con arreglos, como ordenar, buscar y comparar.
Clase utilitaria Objects: Proporciona métodos auxiliares para trabajar con objetos, incluyendo comprobaciones de igualdad y valores nulos.
Programación modular: Consiste en separar el sistema en componentes con responsabilidades específicas que puedan trabajar juntos.
Arquitectura: Es la estructura general de un sistema de software y la forma en que sus componentes se relacionan.
Capa: Es una división lógica de una aplicación según responsabilidades. Por ejemplo, presentación, lógica de negocio y acceso a datos.
Modelo de dominio: Es la representación de los conceptos, reglas y relaciones importantes del problema que el software intenta resolver.
Lógica de negocio: Son las reglas y procesos que determinan cómo funciona una aplicación según el problema que intenta solucionar.
Responsabilidad de una clase: Es la tarea o conjunto de tareas relacionadas que una clase debe realizar dentro del sistema.
Principio de mínima sorpresa: Busca que las clases y métodos se comporten de una manera coherente y esperada para quien utiliza el código.
Refactorización: Es el proceso de mejorar la estructura interna del código sin cambiar su comportamiento externo esperado.
Legibilidad: Es qué tan fácil resulta para otra persona comprender el código. Los nombres claros, responsabilidades bien definidas y estructuras simples mejoran la legibilidad.
Mantenibilidad: Es la facilidad con la que un programa puede modificarse, corregirse o ampliarse.
Escalabilidad: Es la capacidad de un sistema para crecer sin que su estructura se vuelva inmanejable.
Test unitario: Es una prueba que verifica una parte pequeña y específica del programa, como un método o una clase.
Mock: Es un objeto simulado utilizado durante pruebas para reemplazar temporalmente una dependencia real.
Stub: Es un objeto o implementación simplificada que proporciona respuestas controladas durante una prueba.
Debug: Es el proceso de encontrar y corregir errores en un programa.
Bug: Es un error o comportamiento incorrecto dentro de un programa.
Buenas prácticas de POO: Consisten en utilizar nombres claros, encapsular los datos, asignar responsabilidades correctamente, evitar duplicación, reducir dependencias innecesarias y utilizar abstracciones cuando realmente aporten valor.
Clase concreta: Es una clase que puede ser instanciada directamente porque no es abstracta.
Clase final: Es una clase declarada con final que no puede ser extendida por otras clases.
Método final: Es un método que una subclase no puede sobrescribir.
Variable final: Es una variable a la que solo se puede asignar un valor una vez.
Constructor privado: Es un constructor declarado como private. Impide que otras clases creen directamente objetos utilizando ese constructor. Puede utilizarse en determinados patrones o clases utilitarias.
Clase abstracta vs clase concreta: Una clase abstracta sirve como base y no puede instanciarse directamente, mientras que una clase concreta sí puede utilizarse para crear objetos.
Objeto mutable vs inmutable: Un objeto mutable puede cambiar su estado después de crearse. Un objeto inmutable conserva el mismo estado durante toda su vida.
Herencia directa: Ocurre cuando una clase extiende directamente otra clase.
Herencia indirecta: Ocurre cuando una clase hereda de una clase que a su vez hereda de otra.
Jerarquía de clases: Es la estructura formada por clases relacionadas mediante herencia.
Clase base: Es una clase utilizada como punto de partida para otras clases mediante herencia.
Especialización: Consiste en crear una clase más específica a partir de una clase general.
Generalización: Consiste en identificar características comunes de varias clases y colocarlas en una clase más general.
Delegación de responsabilidades: Consiste en permitir que el objeto que tiene el conocimiento adecuado sea quien realice una determinada tarea.
Dependencia fuerte: Ocurre cuando una clase está muy ligada a una implementación específica, dificultando los cambios.
Dependencia débil: Ocurre cuando una clase depende de abstracciones o contratos y puede trabajar con diferentes implementaciones.
Abstracción de datos: Consiste en mostrar las operaciones importantes sobre los datos y ocultar la forma interna en que estos son almacenados o procesados.
Abstracción de comportamiento: Consiste en definir qué puede hacer un objeto sin obligar al usuario a conocer cómo internamente realiza esa acción.
Encapsulamiento vs abstracción: El encapsulamiento se enfoca en proteger y controlar el acceso al estado interno, mientras que la abstracción se enfoca en ocultar complejidad y mostrar solamente lo importante.
Herencia vs composición: La herencia representa normalmente una relación "es un", mientras que la composición representa una relación "tiene un". La composición suele ofrecer mayor flexibilidad cuando no existe una verdadera relación de especialización.
Polimorfismo por interfaz: Permite que diferentes clases implementen la misma interfaz y puedan ser utilizadas mediante una referencia del tipo de esa interfaz.
Polimorfismo por herencia: Permite que objetos de diferentes subclases sean tratados mediante una referencia de su clase padre y respondan según su implementación concreta.
Contrato de comportamiento: Es el conjunto de acciones que un objeto promete poder realizar mediante una interfaz o abstracción.
Programar contra una interfaz: Significa declarar dependencias utilizando tipos abstractos como interfaces en lugar de clases concretas cuando sea apropiado. Esto facilita cambiar implementaciones.
Principio de sustitución: Indica que una implementación concreta debería poder utilizarse en cualquier lugar donde se espera la abstracción que implementa, respetando el contrato establecido.
Acoplamiento temporal: Ocurre cuando una clase necesita que otra realice ciertas operaciones en un orden específico para funcionar correctamente.
Acoplamiento lógico: Ocurre cuando varias clases están relacionadas porque utilizan decisiones o estructuras internas similares, aunque no exista una relación clara de dominio.
Diseño limpio: Busca crear software fácil de comprender, modificar, probar y mantener mediante responsabilidades claras, dependencias controladas y abstracciones adecuadas.
Clean Code: Es un conjunto de prácticas y principios orientados a escribir código claro, simple, expresivo y mantenible.
Nombre significativo: Es un nombre de variable, método o clase que comunica claramente qué representa o qué hace.
Método pequeño: Es un método que tiene una responsabilidad clara y limitada, facilitando su comprensión y prueba.
Clase con demasiadas responsabilidades: Es una clase que intenta encargarse de muchas tareas diferentes. Puede ser una señal de baja cohesión y violación del principio de responsabilidad única.
God Object: Es una clase que concentra demasiadas responsabilidades y conocimiento del sistema. Generalmente dificulta el mantenimiento y aumenta el acoplamiento.
Refactorización de una clase: Consiste en reorganizar una clase para mejorar su estructura, responsabilidades y legibilidad sin cambiar el comportamiento esperado.
Acoplamiento y cohesión: Un buen diseño orientado a objetos normalmente busca bajo acoplamiento entre clases y alta cohesión dentro de cada clase.
API pública: Es el conjunto de elementos de una clase o componente que están disponibles para ser utilizados desde fuera.
Interfaz pública: Es la parte visible de una clase que otras partes del programa pueden utilizar sin conocer sus detalles internos.
Implementación: Es el código interno que hace posible el comportamiento definido por una interfaz, clase o método.
Detalle de implementación: Es una parte interna de cómo funciona una clase que no debería ser necesaria para quien solamente utiliza su interfaz pública.
Ocultamiento de información: Consiste en esconder detalles internos que no deberían ser conocidos ni modificados directamente desde otras partes del sistema.
API vs implementación: La API indica cómo utilizar un componente, mientras que la implementación contiene la lógica interna que hace posible su funcionamiento.
Constructor y método: Un constructor inicializa objetos y tiene el mismo nombre de la clase sin tipo de retorno. Un método representa una operación y puede tener cualquier nombre válido y un tipo de retorno.
Atributo y variable local: Un atributo pertenece a una clase u objeto, mientras que una variable local existe dentro de un método, constructor o bloque específico.
Objeto y referencia: El objeto es la instancia real creada en memoria; la referencia es la variable mediante la cual podemos acceder a ese objeto.
Clase y objeto: La clase es el molde; el objeto es una instancia concreta creada a partir de ese molde.
Estado y comportamiento: El estado representa los datos actuales del objeto, mientras que el comportamiento representa las acciones que puede realizar.
Mensaje: En el contexto de POO, puede entenderse como una solicitud enviada a un objeto para que realice una operación, normalmente mediante una llamada a un método.
Pasar mensajes: Es el concepto de que los objetos interactúan solicitándose acciones mediante sus métodos.
Colaboración entre objetos: Es la interacción entre diferentes objetos para cumplir una tarea mayor dentro del sistema.
Delegación: Un objeto puede pedirle a otro objeto que realice una tarea específica en lugar de hacerla directamente.
Acoplamiento entre objetos: Representa cuánto necesita un objeto conocer o depender de otros objetos para funcionar.
Polimorfismo: Permite utilizar diferentes objetos mediante una misma abstracción y obtener comportamientos diferentes dependiendo del objeto concreto.
Abstracción: Permite trabajar con una representación simplificada de un concepto sin preocuparse por todos sus detalles internos.
Encapsulamiento: Protege el estado interno de los objetos y controla cómo otras partes del programa pueden interactuar con él.
Herencia: Permite reutilizar y especializar comportamiento mediante una relación entre una clase general y una clase más específica.
Los cuatro pilares de la POO: Son encapsulamiento, abstracción, herencia y polimorfismo. Estos principios forman una parte fundamental del pensamiento orientado a objetos.
Encapsulamiento + abstracción + herencia + polimorfismo: En conjunto permiten construir sistemas donde los datos están protegidos, la complejidad se oculta, el comportamiento puede reutilizarse y diferentes objetos pueden responder de distintas formas ante una misma operación.
Programación orientada a objetos en Java: Es el uso de las características de Java para representar entidades mediante clases y objetos, organizando sus datos y comportamientos y aplicando principios como encapsulamiento, abstracción, herencia y polimorfismo.
Objetivo de la POO: El objetivo no es simplemente crear muchas clases, sino organizar el software de manera que sus responsabilidades, datos y comportamientos estén correctamente distribuidos, facilitando la reutilización, mantenimiento, comprensión y evolución del programa.
